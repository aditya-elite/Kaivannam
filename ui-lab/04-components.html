Components

Four places where the design vocabulary was written down but never actually reached the component. These are the least speculative items in the lab — each one is closing a gap between the spec and the build.

1 · Hairline form fields

§2.4 is explicit: rules over boxes, because the reference is editorial rather than app-like. The registration form — the longest flow in the product — is still entirely bordered boxes.

Text input

CSS only
Now — boxed
Proposed — ruled
Tab into both columns. The focus ring is unchanged — 3px, offset, never animated — so the accessibility contract holds; the rule beneath simply takes over from the box. One real trade-off: a boxed field advertises "you can type here" more loudly, which matters for users with low digital literacy. Worth a look at the empty state before rolling this across the whole flow.

Try it on one step first, not all four.

4 · The printed tag

This is the only part of Kaivannam that becomes a physical object. It currently prints like a web page that happens to have a QR code on it.

Maker's mark
  • Cut marks at the corners — tags get cut out with scissors.
  • Fold line so the tag can hang double-sided over a garment edge.
  • Signature rule — the artisan signs the physical object. That is the one credential a counterfeiter cannot copy from the database.
  • Tabular tracked ID from study 02, because this is where it gets read from.
Everything here lives in @media print, so it adds nothing to the screen bundle. globals.css already strips chrome for print — this fills in what should be there instead.

The highest-leverage physical touchpoint in the product.

Sequencing. Do the tag (4) and the tier seal (2) before the card (3). The card is the most visible but the other two are the ones that change whether somebody trusts the object in their hands, which is the entire point of the product.
